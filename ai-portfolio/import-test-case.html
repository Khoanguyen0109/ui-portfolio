The Context
Market Research
You can't acquire a customer
if they can't bring their data.

Katalon True Platform was gaining traction, but conversion from competitors stalled. The blocker wasn't pricing or features. It was data lock-in.

QE teams had years of test cases in TestRail, Qase, or Excel. Switching to a new platform meant re-creating everything from scratch, a cost no team could justify. We had to remove that wall.

The goal wasn't just an import tool. It was a customer acquisition mechanism. A frictionless migration experience that made switching feel safe, fast, and worth it.

The blocker
QE teams had up to millions of test cases in competitor tools. No migration path = no switch, no matter how good the product.
The constraint
3 weeks from brainstorming to shipped. No room for ambiguity. Every design decision had to be right the first time.
The opportunity
Competitors had brittle, confusing import flows. A smoother, smarter migration experience was a direct competitive differentiator.

Competitor import flows dissected, in hours, not days
Used Claude to systematically analyse TestRail and Qase import UX, extract pain points from user reviews, and map the 3 critical gaps before the first PM meeting. Walked in with a differentiation strategy, not questions.

Architecture Claude · Figma
3-step wizard + all edge cases mapped before any screen work
Claude helped map every decision point: empty states, admin-locked fields, conflict types, error recovery paths. The full flow was validated with PM before opening Figma. Zero structural rework after review.
Flow locked, edge cases covered before design
3
Prototyping Claude Code · VSCode
Interactive prototype built same day, live in engineering review
Built a functional HTML prototype of the mapping table, conflict states, and progress modal with Claude Code + VSCode. Engineers reviewed live interactions, not static screens. Feedback incorporated same session.
Alignment in 1 session, not 3 rounds
4
Refinement Figma
High-fidelity focused on judgment: status states, error tone, empty states
Figma work was focused on decisions AI can't make: the exact wording of conflict warnings, how to rank error severity visually, what "Requires Admin to configure" should look and feel like to a non-admin user.
Specs shared with engineering in parallel

Embedded post-handoff, QA cycles treated as design validation
Stayed in QA builds reviewing import edge cases, fixing UI gaps immediately, looping PM when requirement edge cases surfaced. Every QA cycle was a final design pass. Shipped experience matched intent.

The User Flow
Interaction Design

Every step designed to
build confidence, not anxiety.

What happens
My design decision
User value + principle
1
Upload file + choose destination
User uploads a CSV or Excel file (one at a time). Selects the folder location before proceeding. AI generation is offered as an alternative via a dismissible banner.
Onboarding Design · Cross-sell
Offer AI generation as an escape hatch, reduce churn before it starts
Some users arrive with incomplete or badly formatted CSVs. Rather than let them fail, the AI generation banner offers a smarter alternative at the moment of friction, turning a potential drop-off into a feature discovery.
User value
Users who aren't CSV-ready find a better path, reducing abandonment at step 1
Progressive Disclosure
2
Map CSV fields to platform fields
System auto-maps recognised fields. QA Lead reviews and adjusts. Each row shows status: Mapped, Skipped, Conflict, Unmapped, or Requires Admin. Inline "Update" resolves issues without leaving the step.
Data UX · Error Prevention
Surface every conflict inline, fix now, not after a failed import
Competitors hide mapping errors until post-import, when data is already lost. Showing conflicts inline, with a direct "Update" action, means every issue is resolvable before any data moves. The 3-stat summary (Mapped / Skipped / Issues) gives an instant health check at the top.
User value
No surprises after import. Every data issue is visible and fixable before it's too late
Error Prevention (Nielsen)
3
Review summary + preview test cases
4 summary stats: total rows, columns mapped, skipped, custom fields to create. Warning banner flags skipped columns. User can paginate through first 5 test cases to verify how data will look in the platform.
Confidence Design · Decision Gates
Give users a final preview before an irreversible action
Import is destructive. There's no undo on 10,000 test cases. Showing a full data preview before the final button gives users the confidence to commit. The warning banner for skipped columns is a last-chance checkpoint, not a blocker.
User value
User commits to import with full visibility. Trust replaces anxiety
Visibility of System Status
4
Real-time import progress
A modal shows live progress: "X of Y created, N failed." Progress bar fills as rows are processed. User knows exactly what's happening. No black-box wait screen.
Feedback Design · Anxiety Reduction
Replace a spinner with a live counter, make progress tangible
For large imports (thousands of rows), an indeterminate spinner is terrifying. Users don't know if it's working or stuck. Showing a live row count ("40 of 48 created") turns waiting into watching progress. Failed rows surface immediately, not in a post-mortem.
User value
No anxiety during long imports. User knows exactly what's happening at every second
Visibility of System Status
5
Import complete, success summary and next actions
Modal shows: rows imported successfully, rows skipped with reason, downloadable error report. Three clear paths: back to test list / import another file / view imported test cases.
End-State Design · Recovery Flow
Acknowledge errors without shame, give a clear path to fix them
A failed row isn't a failure if the user knows exactly which rows and why. The error report download closes the loop. Users can fix issues and re-import. The three-action footer ensures every outcome (full success, partial, retry) has a clear next step.
User value
Every outcome, success or partial, ends with clarity and a clear next step

Step 1: Upload File
1
Upload file + choose destination
User drags a CSV or Excel file into the upload zone, or browses to select. They pick their folder destination first, so imported test cases land exactly where they want. An AI generation banner offers a smarter alternative if their file isn't ready, reducing step-1 abandonment.
Step 2: Fields Mapping
2
Map CSV fields → platform fields
System auto-maps recognised columns. The QA Lead reviews each field, adjusting mappings, resolving conflicts inline, or creating new custom fields on the spot. A 3-stat summary (Mapped / Skipped / Issues) gives instant health visibility. Every issue has a direct "Update" action, no dead ends.
Step 3: Review & Import
3
Review summary + preview test cases
Before committing, the user sees a full summary: total rows, columns mapped vs skipped, custom fields to create. A warning banner flags any columns that will be skipped. A paginated preview shows exactly how each test case will appear in the platform, confidence before an irreversible action.
Step 4: Importing in progress
4
Live progress, row by row
A modal shows real-time import progress: rows created vs rows failed, and a live progress bar. For large imports with thousands of test cases, users see exactly what's happening at every moment. No spinner, no guessing. Failed rows surface immediately, not after waiting.
Step 5: Import Complete
5
Clear outcome, with a path for every result
The completion modal shows exactly what happened: rows imported, rows skipped, and why. An error report is downloadable so teams can fix issues and re-import cleanly. Three clear next actions, back to list, import another file, or view imported cases, ensure every outcome ends with momentum, not confusion.
